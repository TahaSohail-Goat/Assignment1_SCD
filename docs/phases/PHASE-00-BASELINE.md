# Phase 00 — Assignment Ingestion, Repository Baseline & Governance

## Objective
Build the authoritative documentation baseline before feature coding.

## Read
- CLAUDE.md
- AGENTS.md
- README.md
- complete `docx/ASSIGNMENT.md`
- docs/DOCUMENT_INDEX.md
- current repository state
- GitHub repository metadata/settings

## Tasks
1. Inspect repository tree, branches, status, current tooling, and current code.
2. Preserve existing work.
3. If the assignment source is a DOCX/PDF outside the repo, store the original under `docx/` unchanged.
4. Produce `docx/ASSIGNMENT.md` as a faithful Markdown transcription.
5. Produce `docx/EXTRACTION_NOTES.md` for extraction ambiguities.
6. Create the full requirement traceability matrix.
7. Extract:
   - problem statement,
   - system contract,
   - repo structure,
   - FRs,
   - NFRs,
   - rubric,
   - deductions,
   - bonus,
   - reflection questions,
   - submission requirements.
8. Create the document hierarchy.
9. Detect installed prerequisites and generate precise setup instructions.
10. Establish GitHub labels and issue templates.
11. Create parent issue `[PHASE-00] Assignment Baseline & Governance`.
12. Create sub-issues for documentation work.
13. At this initial point, assign current documentation work only to the real current collaborator. Do not invent the absent partner as a collaborator.
14. Create the issue branch and a documentation PR.
15. Do not merge.

## Definition of Done
The assignment is fully searchable, traceable, and the repo is governed before implementation begins.
